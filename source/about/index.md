## 我的 AI Native

我希望交给 Agent 一件事，它能自己查到现场，按授权做完，把结果留下来。家里先拿运维试。比如推理服务掉线，监控告诉 Agent 哪个实例、什么时候开始报错，Agent 查进程和日志，再带着证据来问要不要恢复。获准后用已有的运维入口处理，发一条真实推理请求确认恢复，最后把这次怎么查的写回知识库。

我给自己定了五个维度。做新项目时，也拿这五条看看哪些已经用得上。

1. **Agent-first OS**。设计系统和工具时，把 Agent 当作操作者。给它可调用的接口、明确的权限和能判断成败的结果。查资产和授权用 JumpServer 的接口，读目标机的状态则走已获准的主机通道。
2. **数据写入即语义化**。记录产生时就带上对象、时间、来源和验证结果。比如推理入口的健康检查通过了，实际模型请求有没有做过，在记录里各写一项。
3. **事件驱动 Agent Swarm**。告警带着对象和时间窗发起调查。调查 Agent 收证据，执行 Agent 接获准的任务，复核 Agent 再查一次实际服务。这条以后还要试告警重复、执行到一半断线等情况。
4. **知识自动回流**。把这次查到的东西、怎么处置、结果能用到什么范围，写回 WeKnora。下回查到旧记录，先对照今天的版本和状态，再决定哪些步骤值得沿用。
5. **自然语言操作面**。我可以直接说「继续上次那台机器的排查」，Agent 要能找回对象、上次的结果和停在哪一步。谁有权改什么，仍按原来的权限和审批来。

我把现阶段叫 **v2.0 AI-Augmented**。家里的 Zabbix 已经能报异常，Agent 能查状态和旧记录，JumpServer 或现有工具负责受控执行，任务结果可以写回 WeKnora。这几段各自用过，目前还是人发起调查。下一步我想先跑通一条告警自动发起只读调查的链路，拿到结果后再由人决定要不要动服务。{% post_link AI-Native的五个维度从接管到自运转 "AI Native 的五维和一次推理故障" %} · {% post_link 把家里的算力全掏出来WeKnora模型保障实录 "WeKnora 的本地模型路由" %}

## 现在的工作

团队建设研发环境时，我从第一批宿主机、共享存储和网络做起。研发进来以后，每个人要能找到自己的环境、读到该读的数据、用上需要的 GPU。换一套驱动或模型环境，还要能照原条件把之前的实验跑出来。模板、权限和构建环境都是为这些事准备的。

也做过用 Go 写的控制面和 GitLab CI，把实验环境复制、构建放到固定的入口。交接时要告诉接手的人，环境基于哪个模板、依赖哪个构建结果、数据从哪取、权限谁来改。隔几周有人来复现实验，可以顺着这些记录重建一份。

GPU 这块做过桌面 vGPU，也做过具身智能模型的边缘推理。桌面看的是多台来宾能不能稳定使用，推理还要看固定节拍下四路共卡会等多久。一组现场对照里，四路模型调用均值从约 204 ms 降到约 115 ms，当时同时改了 GPU 切分和内存放置。这个数是模型调用的实测，我把测试条件和其它几轮的结果都放在{% post_link PVE双宿主机与GPU切分实录 "PVE 和边缘推理那篇" %}。

身份和远程运维这块，我做过{% post_link 三台域控部署实录 "跨站点域控" %}，也做过{% post_link JumpServer企业版部署与健壮性工程 "JumpServer 的目录接入和资产授权" %}。目录、堡垒机和共享存储往往是研发拿到机器时先要用到的三样东西。我把它们跟推理环境放在同一次交付里检查。
